Règles Générales du Projet Tutoré Chaque binôme est responsable de son dépôt GitHub, de la qualité du code, et de la présentation en soutenance. Les règles ci-dessous sont obligatoires.  1.1 Organisation GitHub 
ℹ  Dépôts GitHub Chaque équipe dispose d'un dépôt dédié sur github.com/sunulabo. Format URL : github.com/sunulabo/uadb-m2-[nomprojet] Dépôt ressources (sujets PDF, document affectation) : github.com/sunulabo/uadb-m2-ressources  Branche Usage main Code stable validé. Tout commit sur main = livrable. Ne jamais pousser directement sur main. dev-etudiant1 Branche de travail de l'Étudiant 1. Exemple : dev-kane ou dev-abdoul. dev-etudiant2 Branche de travail de l'Étudiant 2. Merge vers main via Pull Request uniquement.   1.2 Convention de Commits Format obligatoire : [Sx] type: description courte en français  Exemple de commit Signification [S1] feat: génération CSV Pandera seed=42 Semaine 1 — nouvelle fonctionnalité [S2] fix: correction watermark 10 minutes Semaine 2 — correction de bug [S3] docs: README avec captures NiFi Documentation mise à jour [S4] perf: RMSE 142→98 kg/ha Semaine 4 — amélioration de performance   1.3 Structure Obligatoire du Dépôt Dossier / Fichier Contenu attendu scripts/ Tous les scripts Python : schema.py, kafka_producer_*.py, streaming_*.py, train_*.py dags/ DAG Airflow MLOps avec BranchPythonOperator docker/ docker-compose.yml — infrastructure complète nifi_templates/ template_nifi_equipeXX.xml exporté depuis l'interface NiFi dashboard/ dashboard_*.py + graphiques PNG générés rapport/ rapport.pdf — livrable final 5-7 pages README.md Noms étudiants, architecture ASCII, docker compose up, captures NiFi, RMSE/R² obtenus
